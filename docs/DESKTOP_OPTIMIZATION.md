# 原生桌宠性能与维护边界

日期：2026-10-23

本轮修改 Windows 原生 Spine 4.1 桌宠。网页、历史 Electron 宿主和本机已安装 EXE 是不同发布单元；网页更新不能代替程序升级。

## 已调整的共同实现

- **输入区域复用**：原先即使重新采样得到完全相同的矩形，也会重新提交 Windows 输入区域。现在只对变化的矩形、首次出现的输入窗口提交；只在调用成功后保存快照。区域清空、显示和隐藏仍执行必要的首次更新。保留 100ms 采样、精确点击检测、细小四肢和低透明度命中策略。
- **采样计算**：每次构建轮廓时预计算三角形系数；在纹理 Alpha 采样前，以保守半平面测试排除不与网格单元相交的三角形。保留多点采样、窄网格与单元交集兜底，不能为了快而恢复下半身穿透。
- **透明表面复用**：已有约 20% 的容量余量，但之前用预留倍率核对边界，动画范围稍变便消耗掉这层余量。现在按实际绘制倍率分别检查上下左右，能装下就继续使用，实际越界才扩容。保留缩放后的延迟缩容、DirectComposition 和透明黑色清屏。
- **可定位的性能日志**：首次开始绘制后的 30 秒，按 2 秒窗口记录动画、几何、表面、输入、CPU 绘制提交与合成提交耗时、表面重建、区域提交/复用及表面像素数。SPINEPET_PERF_LOG=1 持续记录，=0 关闭。CPU 提交耗时不是 GPU 时间或显卡占用。
- 不改模型 ID、素材目录、配置或更新地址，不把清空素材和重新下载作为升级路径。

## 源码所有权与固定上游

原生上游仍固定为 KAIDO-YONAGI/My_SpinePet 的 6690e986b4da31dc89337794bcef1b45e6531303。四个需要持续维护的渲染/输入模块迁入 native-desktop/rendering/，三个纯几何/快照服务显式输入输出。对应大段 PowerShell 字符串替换已经退役；余下兼容钩子继续检查唯一锚点。

upstream-overlays.json 声明原始源文件摘要。Apply-RenderOverlays.ps1 先校验全部文件及新增模块是否冲突，再安装类型源码并生成 exact-source 摘要收据。上游变更不能静默套用旧适配。Test-RenderOverlayContract.ps1 验证错误源被拒绝且不会发生部分替换。

对应 GPL 源码产物包含固定上游、完整 native-desktop/、安装摘要及实际重建顺序，包含所有构建脚本、模块和依赖版本。

## 验证

Windows 发布流程执行：

1. 覆盖安装前的输入摘要预检与失败不替换测试。
2. 随机三角形的参考算法对照、窄网格/边缘交集、输入快照更新和失效。
3. 实际 Direct3D/DirectComposition 表面复用、越界扩容和透明像素读回；实际 Win32 输入窗口在相同区域下避免重复提交。
4. 同一固定 BD2 资源在四组缩放/动作时刻的实际网格与下半身点击区域回归；连续帧输出 CPU 轮廓采样均值、P95 和线程分配量。
5. 上游原生渲染提交、透明/混合模式、鼠标区域、调度等回归，以及真实角色导入、双目录安装、更新装包与独立安全扫描。

测试结果保存为 native-desktop-regression-results。功能验收与性能数据来自 Windows CI，不能据此承诺用户 RTX 5060 Ti 的实际帧率。仅完整成功且通过发布门禁的构建才能进入自动更新源。本轮没有扩展 Live2D 或其他 Spine 版本的原生支持。

## 本轮测量记录

[Windows 构建 0.1.148](https://github.com/tyqittle/anime-character-archive/actions/runs/39976738593)使用源提交 `81de4b37912ffa98cdca50f34598c16fe43e4c58`，37 项原生测试通过。真实双目录安装测试也已通过。[仓库检查](https://github.com/tyqittle/anime-character-archive/actions/runs/39976738711)通过 127 项 Node 与 33 项 Python 测试。

同一 BD2 固定样本、650 像素目标高度下，预热后的 12 帧 CPU 轮廓采样均值为 2.678ms，P95 为 7.438ms，测试窗口平均线程分配为 1153 字节/次。这里测的是轮廓计算，不含完整动画帧或 GPU 时间；这是单次 CI 测量，没有旧版同机对照，不能换算为性能提升百分比或用户设备帧率。

实际 D3D 表面测试中，100 次范围渐增仍只分配 1 次表面，确实越界后才发生第 2 次分配；实际输入窗口测试中，相同矩形刷新不会再次提交，矩形变化与清空仍会提交。最终可更新安装包以同一工作流的安全审计和发布任务均成功为准。
