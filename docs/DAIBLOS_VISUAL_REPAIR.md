## 一轮诊断的证据结构

运行 `.github/workflows/daiblos-visual-audit.yml`（自动监听诊断脚本提交，也支持手动运行）：

1. `daiblos-visual-0..9`：每套可加载模型的实际 Canvas PNG、单条结果、Atlas 旋转分布、运行时贴图与区域尺寸、Mesh/Region 附件数量、越界 UV 检查。
2. `daiblos-animation-sweep`：Pelorovis03（异常）和 Alps03（对照）的多个动作截图与动作名称。验证是否是默认动作/皮肤选择导致的部件分散。
3. `daiblos-atlas-ab`：相同模型在原生和兼容补丁版 Spine 3.8 下的对比截图。

这些结果是诊断，不会自动改变目录或声称正常。

## 根因判定与修复边界

- **仅某个动作损坏**：检查骨骼动画、默认动作选择、皮肤/插槽激活配置。把修复记录为模型元数据里的正确动画，不用游戏名硬编码。
- **所有动作损坏，原生和补丁相同**：检查源 JSON、Atlas、PNG 是否同一导出版本；运行时实际 PNG 宽高是否与 Atlas page size 一致；附件 Region/Mesh 的 UV、网格顶点及剪裁数据。怀疑源文件时向上游寻找一致的导出包，不能从其他皮肤借图。
- **仅补丁损坏**：根据附件类型、旋转坐标和运行时版本修正引擎适配，并覆盖正常与异常模型的 WebGL 回归；不得对整个游戏绕过资源验证。
- **贴图几何正确但颜色或局部透明异常**：检查 PMA、混合模式、贴图颜色空间，不用锐化或缩放掩盖。
- **不能复现或证据不足**：保持原始目录和素材，不清除，不标记修复成功；在预览或目录状态中保留待验收记录。

## 视觉验收标准

完成每套疑似异常模型的默认动作及至少一个稳定循环动作截图审查、原生/补丁对比、骨骼/Atlas/PNG 同源校验，再发布模型级修复。自动连通性指标仅用于排队人工审查，不等于人物拼接正确。修复共享层必须对 Alps03/05 等既有正常模型做回归；新增游戏走同一引擎适配与验收流程。
