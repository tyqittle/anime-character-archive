# 扩充立绘时的兼容检查

核验基线：GitHub main `08507709118aa96be13c292ff523d9893f2c9ff6`，16 个注册目录、4,684 个模型记录。对象是动态模型及其皮肤，不把目录条数当成全部游戏均已完整收录的证明。

## 发现与处理

| 风险 | 处理 |
| --- | --- |
| Live2D 导入原来仅按 `sourcePath` 更新，同一相对路径可能来自不同仓库或游戏 | 两种引擎均按稳定 ID 合并；跨目录 ID 冲突、角色/皮肤/引擎变化、重复输入均在写入前拒绝。新增游戏不会替换另一个游戏的同名路径 |
| 已有 ID 的来源更新可能覆盖旧预览；长时间扫描期间还可能出现新的目录修改 | 默认保留旧来源与预览。来源替换须明确列出 `--update-existing ID`，替换后清除旧预览证据；写入前重新读取目录，并以临时文件原子替换 |
| 本地快照比 main 少 3 个目录、104 个已发布条目 | 固定提交下载并校验 Git blob，恢复目录、设置和预览。不得把旧本地注册表覆盖到当前 main |
| 新增标准变体可能改变旧链接的默认去重目标 | 兼容检查比较共同去重规则下的旧链接目标；变更必须按 ID 记录准确的前值、后值和原因 |
| 目录保留但预览文件遗漏、串用或被改写 | 检查有效预览是否丢失、来源身份是否过期；核验本地图片路径、文件存在性和 SHA-256 |
| 为一个异常模型引入全局取景启发式，可能影响旧角色的远处装饰 | 待发布播放器改为单模型数据声明。默认不筛掉任何有效网格；策略进入来源身份，切换角色清除，真实模型重新采集 |
| Cubism 切换时旧的未完成加载仍等待长超时 | 待发布播放器即时结束旧 setup 等待、销毁旧候选并清理计时器；迟到回调不能覆盖新模型 |

`scripts/catalog_compatibility.mjs` 提供可重复的比较。`scripts/check_catalog_update.mjs` 为 CI 读取实际 push/PR 基线，浅克隆缺少基线时只补取该提交。检查失败则该验证任务失败。分支保护和其他发布工作流是否强制依赖该验证，是另一层仓库设置；本次没有把检查结果宣称为 GitHub 已禁止所有绕过路径。

`data/catalog-compatibility-changes.json` 只声明逐 ID、逐字段且前后值准确的修复。允许字段修复不豁免预览来源或文件摘要检查，也不能作为整款游戏的通行证。

## 本地结果

- 4,684 个基线 ID 全部保留，模型文件地址、皮肤、目录归属和默认链接目标保持兼容；当前草案共 4,741 项，其中 57 项为之前批次的未发布扩充。
- 3 项单模型解释修复单独记录：`gc-girl04-l2d05` 的一个停放网格；`ec-50010001` 和 `ec-500180` 的两像素 Atlas 边界。其他模型不启用这些策略。
- 当前草案经统一预览流程转码 60 帧、拒绝 0 帧；57 项新增及 3 项旧故障模型均有对应源身份的真实预览。不能据此推断全部游戏的资源覆盖完整。
- 20 个旧模型代表样本实际加载、双帧动态、动作、缩放通过，包含两种碧蓝航线旧提供方、Cubism2/3 和 Spine。异常取景模型切回旧角色的同 iframe 检查通过，策略已清空。
- 172 项 Node 检查、42 项 Python 检查通过；涉及播放器变更后另做最终浏览器回归。完整站点还有未逐项实际播放的模型。

复现草案兼容检查：

```sh
node scripts/catalog_compatibility.mjs --base-ref BASE_COMMIT --changes data/catalog-compatibility-changes.json --verify-previews --output tmp/catalog-compatibility.json
npm test
npm run check
npm run test:python
```

当前工作目录是本地导出快照，没有 `.git`；不能把本地文件改动等同于已提交或已上线。本次先独立提交导入与 CI 的兼容保护，播放器和 57 项扩充仍按各自验证结果另行发布，避免夹带上游并发的桌面和 UI 改动。
